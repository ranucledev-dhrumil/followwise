# Decisions for PLAN-0017 (authored by the orchestrator; the planner must not copy or change this text)
Executor step: append the five rows below to README section 14.1 exactly as written (table format of the earlier rows), in order.

| D-117 | Typed API layer: the backend OpenAPI document is exported by a backend test to docs/api/openapi.json (committed). Frontend types are generated from it with openapi-typescript (a dev dependency whose version the planner verifies against Spring Boot 4.1 and springdoc 3.1) into frontend/src/lib/api/schema.ts (committed, never edited by hand) by the npm script api:types. Typed wrapper functions per backend area live in frontend/src/lib/api/ and all use the existing apiFetch (single-flight refresh, retry rules of D-56). The founder check is that api:types leaves no uncommitted diff. If export or generation is not feasible, the planner lists it under DECISION NEEDED instead of hand-writing types. |
| D-118 | Routes and navigation: /app lists the apps of the current workspace (the first workspace of GET /api/me; a workspace switcher appears only when the user has more than one); /app/new is the template picker and create flow; /app/apps/[appId] is the app home. The app shell shows the app name and an app switcher; navigation items come from the forms response (labels such as Tenants or Clients come from the definition, never hard-coded) and an item appears only when its screen exists, so there are no dead links. Every route redirects to /login when the session cannot be restored (D-56). |
| D-119 | UI states and errors: every data screen implements loading (skeleton), empty (one sentence and one primary action), error, and success states, each covered by a test. Errors map the problem+json type or status to fixed friendly messages in one module (401 handled by the client, 403 shows a no-access message, 404 a not-found message, 409 and 422 show the server's fixed detail, 429 shows the Retry-After countdown, 503 and network errors show the waking-up message with a retry button), and never display raw server text that is not on the list. Field limits and labels come from the forms endpoint, never hard-coded in the frontend. Dates are ISO yyyy-MM-dd strings parsed manually (never new Date on a date-only string); money is integer cents formatted with Intl.NumberFormat for the app currency and never stored as a float. |
| D-120 | Template picker and create app: GET /api/templates lists the two templates; the frontend owns a small table of friendly descriptions keyed by template key (Rental Property Manager: track rent, late fees and tenants; Client Document Tracker: collect and track documents from clients); the create form asks for a name (1 to 100 characters, no control characters or angle brackets, same limits as the backend) and a time zone chosen from Intl.supportedValuesOf('timeZone') with the browser zone preselected; the call is POST /api/workspaces/{id}/apps; success goes to the app home; 409 limit_exceeded explains the app limit in plain words; creation is not retried automatically (D-56). |
| D-121 | App home is the dashboard: GET .../dashboard renders every widget generically by type: count widgets show the number, sum widgets show formatted money, list widgets show their rows with the total count and no links yet (the screens they would open do not exist), completion widgets show a percentage per party; an UNAVAILABLE widget shows a neutral note with its reason in plain words; a month selector limits the choice to 24 months before and after the current month and shows the month the server returned; generatedAt is shown as "updated"; a dashboard_timeout 503 shows a retry message; all text uses the labels from the response; a widget never crashes the page (an unknown widget type renders as a neutral card). Status is never shown by colour alone (DESIGN.md). |
